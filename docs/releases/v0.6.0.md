## rookery v0.6.0

v0.6.0 gives Slack a real **Stop** button for the agent, catches rookery up with the latest Claude Agent SDK (0.3.303) and Codex CLI (0.163.0), and fixes cost accounting that was quietly over-counting.

_34 commits since v0.5.0._

### ⏹️ Stop the agent from Slack

Slack's agent sessions show a native **Stop** button while the agent is working. Rookery now wires it up.

- **Stop actually stops.** Pressing it aborts the master's current turn *and* cancels any messages still queued in that thread, so the agent doesn't immediately pick the next one up. The thread gets a short "stopped" confirmation. Workers the master already spawned keep running (stop them separately), and the confirmation tells you how many are still going.
- **No leftover output.** The stopped answer doesn't spill into a new message after you press Stop.
- **"Waiting for you" status.** While an approval or a question card is waiting on an answer, the thread shows as waiting for input instead of "working". Cancelled cards are replaced with a single "cancelled" line.
- **Rename sync.** Renaming the session in Slack renames it in the desktop app too.
- Status now uses Slack's new `agents.sessions` API, which also works in `@mention` channel threads. Workspaces without the agent feature automatically keep the old behavior.
- **Setup:** in your Slack app settings, add the `agent_session_stopped` and `agent_session_title_changed` bot events. Without them everything else keeps working, but the Stop button stays inactive.

### 💸 Accurate cost accounting

- **Claude cost was over-counted, and is now fixed.** The SDK reports cost as a running total for the whole conversation, and rookery was adding that total on every turn. Masters, resumed workers, and long-running workers all showed inflated spend, and the cost budget guard could trip early. Rookery now bills only each turn's own cost, including across daemon restarts, resumes, and forks. Totals already recorded before this release are not rewritten.
- **New Codex models are priced.** gpt-6.1-sol, gpt-6-sol, gpt-6-astra, gpt-6-luna and gpt-5.6-sol/terra/luna previously counted as $0, which also left the Codex cost budget blind.
- **Codex usage gauges fixed.** The weekly limit was being shown in the 5-hour gauge.

### 🔄 Claude Agent SDK 0.3.303 & Codex CLI 0.163.0

- **The master's context stays fresh every turn.** With the new SDK, the master's injected context (recent memories, repo list, agent name, capability instructions) could freeze at its first-turn values. It is refreshed every turn again.
- **Codex default model is now `gpt-6.1-sol`.** The previous default, `gpt-5.5`, is rejected for ChatGPT-account Codex logins, so Codex workers and masters using the default failed to start.
- **Codex `max` / `ultra` effort now apply.** They were previously downgraded or ignored. Levels a model doesn't support are dropped instead of failing the turn.
- **Codex CLI 0.146.1 or newer is now required.** Older CLIs get a clear "please upgrade" error. On 0.151.0+, resuming a long Codex thread no longer reloads its whole history.
- The SDK's new `informational` messages show up as readable notices instead of the bare word "informational".
- MCP servers that fail to start in a Codex session now show as unavailable in Capability Center instead of "applied".

### 🧹 Fixes

- Closing a dialog while it is animating out no longer updates an unmounted screen. This also fixes an intermittent desktop test failure.

### 📦 Notes

- macOS builds are signed and notarized. Linux AppImage and unsigned Windows installer builds are included in the release assets.
- Updater metadata and stable latest-download filenames are published for all supported desktop platforms.
