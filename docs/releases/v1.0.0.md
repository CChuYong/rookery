## rookery v1.0.0

v1.0.0 is the release where the desktop app grows up into a workbench. The whole renderer was redesigned in the style of an IDE, and a full UI/UX audit was worked through end to end. You can now steer a worker that is already busy, and stop one of its background tasks without stopping the worker. Every conversation gets Standard/Fast speed controls, and you can attach images to masters, workers and Side conversations.

_39 commits since v0.6.0._

### 🖥️ An IDE-style desktop app

- **Redesigned renderer.** The app now looks like a quiet IDE (the VS Code / Zed family): neutral greys, the system font, a compact type scale, fixed bar heights and a real status bar. The orange accent is kept for focus and the current item, and blue only ever means "running".
- **Panels that behave when you resize.**
  - The conversation has a minimum size, and the side panel stays between 220 and 440px.
  - On a narrow window the side panel hides itself, and its toggle shows that it was auto-hidden.
  - Widen the window again and it comes back at the width you chose.
  - Hiding the terminal keeps your shell's size. Opening it starts a shell.
  - Reset layout can be undone.
- **Simpler chrome.**
  - The collapsed sidebar is a navigation rail.
  - One bell in the status bar holds the attention queue and the OS-notification switch.
  - Narrow headers move their extra items into a "…" menu, so nothing disappears.
  - Session and worker headers share one control order.
- **Calmer composers.**
  - Model, effort, permission mode and speed live in one menu, so the composer footer stays on one row.
  - The conversation, New session and New worker composers share one layout and submit with Enter.
  - Messages you are sending appear in the transcript, and a failure shows one error in one place.
- **New worker as a full page.** Spawning a worker opens a page like New Session instead of a cramped dialog. It shows the task box, the repo inline in the heading, and an optional GitHub/Linear ticket. Your draft, including the picked ticket, is kept per repo, and Back after a spawn doesn't reopen an empty form.
- **Whole-branch diff.** Open everything a worker changed since its branch forked from its base, from the worker menu or the Git panel.
- **Honest states.**
  - Every list and panel tells loading, empty and failed apart, and Retry shows its progress.
  - A folder that isn't a git repository no longer reads as "no changes".
  - Nothing is stuck on "loading…" or "checking…" anymore.
- **Settings you can trust.**
  - One Save bar, with an unsaved-changes count and Revert.
  - Leaving with unsaved edits asks first.
  - API keys are cleared only after the save succeeds.
  - Model defaults live together.
- **Clearer automation and Capability Center.** The automation form asks for the action before the run settings, and next runs show in your local time. Capability Center uses one set of names and no internal jargon.
- **One word per idea.** Korean and English each use one term per concept (interrupt a turn vs stop a worker, restore a checkpoint vs discard git changes, and so on). Korean copy is consistent throughout, and Slack and CLI notices use the same terms.
- **Keyboard and accessibility.**
  - Focus returns to where you were when a menu or dialog closes, and Escape closes only the top layer.
  - File tree and list actions work from the keyboard.
  - Korean IME input no longer submits early.
  - Approval cards never steal focus while you type.
  - New shortcuts: ⌘B (sidebar, or bold with a selection), ⌘N (new item), ⌘, (settings) and ⌘[ / ⌘] (back/forward). ⌘W closes the active editor tab.
- **Read-only outside files.** Files outside the work folder that an agent mentions now open read-only instead of failing.
- **Safer edits.** A file that failed to load can no longer be saved over the original. Destructive actions confirm once, and a double click won't run them twice.

### 🧭 Steer busy workers, stop single background tasks

- **Steering.** A message to a busy worker is delivered into the turn it is running instead of waiting for the turn to end. Codex uses `turn/steer`; Claude uses streaming input. When that isn't possible, the message waits for the next turn as before.
  - A message that was accepted but never read before a stop, recover or stream error comes back as a retryable error, so it isn't lost silently.
  - Workers trust mid-task operator messages but ignore the same wording when it appears in a file or command output.
- **Stop one background task.** A worker's listed background tasks (for example a long `run_in_background` shell) can be stopped one at a time from the desktop, without stopping the worker. Claude workers only.

### ⚡ Speed controls and 🖼️ native images

- **Standard / Fast** for every master, worker and automation, for both Claude and Codex.
  - Changes apply at the next turn.
  - Defaults are set per provider and role in Settings.
  - Fast falls back to Standard on Codex models that don't support it.
  - Cost shows whether it is reported, estimated or unavailable, instead of a reliable-looking zero.
- **Image attachments.** Pick, drop or paste images into master, worker and Side conversations. They are sent natively to Claude and Codex, survive reconnects, and open in a preview.
  - Identical uploads are stored once.
  - Images no conversation uses are cleaned up after 7 days without use.

### 🔄 Claude Agent SDK 0.3.325 & Codex CLI 0.169.0

- Updated to Claude Agent SDK 0.3.325.
- Codex protocol types are now checked against CLI 0.169.0, which is also the new minimum supported version.
- Pricing added for `gpt-6.1-terra`.

### 🧹 Fixes

- Worker diffs (desktop, and the master's `view_worker_diff`) show only what the branch changed since it forked. Before, commits that landed on the base later showed up as reverse edits. This needs git 2.30 or newer, and falls back on older git.
- Codex workers stay usable across daemon restarts and on models without Fast.
- The daemon tolerates a symlinked home directory.

### 📦 Notes

- **One-time layout reset.** Saved dock layouts in an old broken shape are reset to the default layout once, the first time a page opens.
- **Builds.**
  - macOS builds are signed and notarized.
  - Linux AppImage and unsigned Windows installer builds are included in the release assets.
  - Updater metadata and stable latest-download filenames are published for all supported desktop platforms.
