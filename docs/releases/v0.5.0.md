## rookery v0.5.0

v0.5.0 makes `ccusage` see Codex spend for the first time — every Codex master and worker rollout is now mirrored into your real Codex home so usage tooling can find it — plus a routine SDK bump.

_10 commits since v0.4.4._

### 📊 Codex usage now shows up in `ccusage`

Rookery gives every Codex master and worker its own isolated `CODEX_HOME` (so sessions don't collide or leak auth), but that meant `ccusage codex` — which only scans a single, real `CODEX_HOME` — could never see any of that spend. Codex usage was invisible to standard usage reporting.

- Every Codex rollout is now **hardlinked** into your real `CODEX_HOME` under `archived_sessions/`, so `ccusage codex` (and anything else that scans `CODEX_HOME`) accounts for it correctly.
- Because it's a hardlink to the same inode, a live worker's ongoing writes need no re-sync, and nothing is ever duplicated on disk.
- Codex itself keeps these mirrored rollouts out of `thread/list` and refuses to resume them, so they show up for accounting only — they can't be picked up as live sessions by mistake.
- The mirror is swept at daemon boot, on every usage-refresh tick, and right before a target's home is torn down, so spend is captured even for short-lived workers. Mirrored history is **never deleted**, so a deleted worker's spend stays accounted for.

### 📦 Notes

- macOS builds are signed and notarized. Linux AppImage and unsigned Windows installer builds are included in the release assets.
- Updater metadata and stable latest-download filenames are published for all supported desktop platforms.
