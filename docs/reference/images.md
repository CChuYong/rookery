# Native image input

The authenticated WebSocket exposes `image.upload {name,mediaType,base64,reqId}` → `image.upload.result {image,reqId}` and `image.get {id,reqId}` → `image.get.result {image,base64,reqId}`. `image` is the authoritative `ImageRef {id,name,mediaType,byteLength,width,height}`. Upload/get never accept filesystem paths or remote URLs.

`session.send`, `worker.send`, `side.start`, and `side.send` accept optional `images: ImageRef[]` alongside `text`. Image-only input is valid. Worker spawning, CLI, tools, Slack and automation retain their existing text inputs. A send validates the entire list against stored metadata and availability before accepting it; tampered, missing or unreadable assets reject the whole input. Queued Master and Worker follow-ups retain refs and resolve bytes only at dispatch, so a file becoming unreadable while queued fails visibly before its echo or provider call. Side start prepares its initial input after the asynchronous provider fork and before `side.started`; preparation failure cleans up the fork and rejects the request once. Prepared execution emits its first Side event after the success reply without reopening image files.

Product bounds are 4 images per message, 3 MiB decoded bytes per image, 8 MiB total per message, 8000 pixels per dimension, 20,000,000 pixels per image, 16 MiB inbound WebSocket frames, and 1 GiB total retained image assets. PNG, JPEG, GIF and WebP are supported. Upload validates canonical base64, exact MIME/signature agreement and parsed dimensions while preserving the original bytes. The zero-transitive-dependency `image-size` 2.1 header parser handles dimensions; fixed magic comparisons close its permissive PNG byte-zero detector. Decoding is bounded before allocation; no pixel decoder, Electron runtime or network fetch is used in the daemon.

`ImageStore` owns `<ROOKERY_HOME>/images/` with a real 0700 directory and opaque UUID v4 filenames written 0600 through exclusive, no-follow temporary creation and atomic no-replace linking. SQLite's append-only `images` migration stores immutable metadata. Metadata/file failures roll back only files owned by that attempted upload. Synchronous reservations serialize concurrent uploads under the daemon's single-owner process; quota also counts crash leftovers conservatively, without following symlinks. Reads are bounded by authoritative metadata and reject symlinks and non-files.

**Retention is indefinite; there is no implicit garbage collection.** Session/Worker deletion never deletes images. Same-provider forks share blob refs and native provider history; cross-provider handoff keeps its existing textual summary and sends only newly attached images natively. Forks, transcripts and persisted desktop drafts may still reference assets. Quota failure retains every existing asset. Crash leftovers consume quota too; this feature adds no deletion API or automatic cleanup policy.

Master/Worker transcript event JSON persists refs only; `messages.content` remains the textual index. Reconnect/history and forks reuse those refs instead of copying payloads. Side echoes also carry refs. Claude receives a finite single-message iterable for image-bearing Master/Side turns and streaming native image blocks for Worker inputs. Text-only Master turns remain string prompts. Codex receives native `image` data-URL items. Provider image payloads never become path text or transcript fields.

Desktop imports native selected files, browser drops and clipboard images; mixed clipboard text is retained. The selected-file IPC reads only a path chosen in its own native dialog, caps allocation before reading, and leaves ordinary files as `@path` mentions. The renderer uploads before decoding any preview. Draft schema v2 migrates v1 strings to `{text, images}` and strips extra image fields before localStorage writes. Failed requests retain the draft; acceptance clears only that draft revision. Historical previews request `image.get` only near the viewport; offscreen components release their data and a 24 MiB data-URL LRU bounds reuse. Missing history has an explicit retry placeholder.

`session.send` now acknowledges validated queue acceptance through `MasterAgent.enqueueTurn`; internal `runTurn` callers still await execution completion. This permits a new desktop draft while an earlier model turn is running. Master user events and Worker message data persist optional `clientMsgId` so consecutive image-only inputs remain distinct live and after replay. A queued pre-echo dispatch failure persists an error carrying `clientMsgId` and a reference-only `retryInput {text, images?}`. The desktop removes its matching pending entry and renders the retryable input, including after reconnect without local pending state. A terminal Worker offers Restore draft and existing worker recovery instead of sending to a terminated Worker. This is failure evidence, not a durable server work queue; daemon restart retains existing queue-loss semantics.
